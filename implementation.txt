# WEXA AI — CognoDB Take-Home Assignment

## Job & Skill Recommendation Graph

Build a production-quality full-stack web application called **TalentGraph** for the Wexa AI CognoDB take-home assignment.

The application is a **Job & Skill Recommendation Graph** backed by **CognoDB**, using the official Neo4j JavaScript driver and openCypher.

The goal is to demonstrate:

* Thoughtful graph data modeling
* Multi-hop graph traversal
* Relationship-based recommendations
* Clean frontend architecture
* Professional UI/UX
* Parameterized Cypher queries
* Error handling
* Seed data
* Maintainable code structure
* AI-assisted development that can be explained clearly in an interview

Do not build a generic CRUD application. The graph relationships must be central to the application's functionality.

# 2. Core Product Concept

Create a platform that helps recruiters or hiring managers discover suitable jobs/candidates based on connected skills, projects and technologies.

The application should demonstrate how graph traversal can answer questions such as:

1. Which jobs match a candidate's skills?
2. Which skills are missing for a particular job?
3. Which technologies has a candidate worked with indirectly through projects?
4. Which candidates are suitable for a particular job?
5. Which related skills could help a candidate qualify for another job?
6. What connections exist between a candidate, their projects, technologies and available jobs?

The application should feel like a small but polished **talent intelligence platform**, not just a database demo.

# 4. Relationships

Use typed relationships.

```text
Candidate -[:HAS_SKILL]-> Skill

Candidate -[:WORKED_ON]-> Project

Project -[:USES]-> Technology

Job -[:REQUIRES]-> Skill

Job -[:POSTED_BY]-> Company

Skill -[:RELATED_TO]-> Skill
```

Relationship properties may be added where useful.

For example:

```text
WORKED_ON {
  role,
  durationMonths
}
```

and:

```text
REQUIRES {
  importance
}
```

# 5. Why Graph Database?

The README must contain a clear section titled:

## Why a graph database?

Explain that the core problem is relationship discovery rather than simple record retrieval.

Example explanation:

Candidates are connected to skills, projects and technologies, while jobs are connected to required skills and companies. A graph database allows the application to traverse these relationships naturally across multiple hops.

For example:

```text
Candidate
   ↓ HAS_SKILL
Skill
   ↓ REQUIRED_BY
Job
   ↓ POSTED_BY
Company
```

or:

```text
Candidate
   ↓ WORKED_ON
Project
   ↓ USES
Technology
```

Explain that a relational database could represent the same data, but relationship-heavy queries would require multiple joins and become increasingly cumbersome as the relationship model grows.

Do not claim that graph databases are always better than relational databases.

Explain that CognoDB is specifically valuable here because the application's primary questions involve connected entities and multi-hop traversal.

# 14. Important Cypher Queries

Create a dedicated directory:

```text
server/src/database/queries/
```

Store Cypher queries separately.

At minimum implement these queries.

## Query 1 — Candidate skills

```cypher
MATCH (c:Candidate)-[:HAS_SKILL]->(s:Skill)
WHERE c.id = $candidateId
RETURN s
ORDER BY s.name
```

## Query 2 — Candidate technologies through projects

This must be a multi-hop traversal.

```cypher
MATCH (c:Candidate)-[:WORKED_ON]->(p:Project)-[:USES]->(t:Technology)
WHERE c.id = $candidateId
RETURN DISTINCT t
ORDER BY t.name
```

## Query 3 — Matching jobs

```cypher
MATCH (c:Candidate)-[:HAS_SKILL]->(s:Skill)<-[:REQUIRES]-(j:Job)
WHERE c.id = $candidateId
WITH c, j, collect(DISTINCT s) AS matchedSkills
MATCH (j)-[:REQUIRES]->(required:Skill)
WITH c, j, matchedSkills, collect(DISTINCT required) AS requiredSkills
RETURN
    j,
    matchedSkills,
    requiredSkills,
    size(matchedSkills) AS matchedCount,
    size(requiredSkills) AS requiredCount,
    round(toFloat(size(matchedSkills)) / size(requiredSkills) * 100) AS matchScore
ORDER BY matchScore DESC
```

Make sure the query is compatible with CognoDB/openCypher.

If any syntax needs adjustment based on CognoDB compatibility, adapt it rather than forcing unsupported Neo4j-specific syntax.

## Query 4 — Matching candidates for a job

Implement the reverse traversal:

```text
Candidate → Skill ← Job
```

Rank candidates by matching skills.

## Query 5 — Related skills

Given a candidate's existing skill, find related skills:

```text
Candidate
→ HAS_SKILL
→ Skill
→ RELATED_TO
→ Skill
```

Use this to display:

```text
Skills you may want to learn
```

# 15. Parameterized Queries

Every Cypher query MUST use parameters.

Correct:

```ts
session.run(query, {
  candidateId
});
```

Never do:

```ts
session.run(`
  MATCH (c:Candidate {id: '${candidateId}'})
`);
```

There must be no string concatenation for user-controlled values.
